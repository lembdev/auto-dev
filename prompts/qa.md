## Что проверить

1. Прочитай issue целиком, критерии Epic и правила Продукта из общей части. Затем тело pull request #{{pull_number}} (`gh pr view {{pull_number}}`) и его diff (`gh pr diff {{pull_number}}` или `git diff origin/main...HEAD` в worktree).
2. Сверь изменения с каждым пунктом «Acceptance criteria» issue: пункт считается выполненным, только если он реализован и покрыт тестом или описан в «Как проверить» тела pull request.
3. Сверь секцию `## Критерии Epic` тела pull request с чек-листом Epic: строки должны совпадать с чек-листом и соответствовать тому, что Задача действительно закрывает.
4. Прогони тесты и линт Продукта сам, так, как написано в его `CLAUDE.md` или `package.json`. Не доверяй словам в теле pull request.
5. Проверь, что правила Продукта (`CLAUDE.md`, глоссарий, `docs/agents`, ADR) соблюдены, тесты не ослаблены и не выключены, коммиты и заголовок pull request в формате Conventional Commits.
6. Если есть прошлый вердикт, убедись, что каждый его blocker исправлен, или что Реализатор обоснованно его отклонил.

## Чего не делать

- Не правь код и тесты, не делай коммитов, не пушь, не меняй тело и заголовок pull request. Если нашёл проблему, опиши её в blockers.
- Не пиши комментарии в issue и pull request.
- Замечания по стилю, именованию и вкусу не блокируют: упомяни их в `summary`, но не включай в `blockers`.

## Вердикт

Последнее сообщение Хода - ровно один JSON такого вида и больше ничего (без пояснений до или после, без code fence):

```
{ "approved": boolean, "summary": string, "blockers": [{ "where": string, "what": string }] }
```

- `approved: true` только когда `blockers` пуст: Задача выполнена по всем критериям, тесты и линт зелёные.
- `blockers`: каждая причина, по которой pull request нельзя влить. `where` - файл и место (или «тесты», «тело PR»), `what` - что не так и что ожидается. Пиши так, чтобы Реализатор мог исправить без уточнений.
- `summary`: два-три предложения о состоянии работы, в том числе неблокирующие замечания.

Если вердикт не распарсится, Оркестратор попросит повторить только JSON; вторая неудачная попытка подряд отправит Задачу в Тупик.
