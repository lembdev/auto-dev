# Обзор Codeman (Ark0N/Codeman): что переносимо в auto-dev

Дата: 2026-11-05. Источник: репозиторий https://github.com/Ark0N/Codeman (ветка master, MIT, 828 звёзд, ~3600 коммитов, последний push 2026-11-05), доки `docs/respawn-state-machine.md`, `docs/reliable-input-delivery.md`, `docs/orchestrator-loop-architecture.md`, `docs/architecture-invariants.md`, `docs/usage-limits-display-plan.md`, `docs/claude-code-hooks-reference.md`. Копии доков: scratchpad сессии, в репо не кладутся.

## Что это

Self-hosted веб-панель поверх tmux/PTY: гоняет интерактивный TUI Claude Code (и ещё ~10 CLI), стримит терминал в браузер через SSE/xterm.js, умеет respawn (idle -> `/update` -> `/clear` -> `/init` -> kickstart), auto-resume после лимита подписки, cron, «оркестратор» цель -> фазы -> промпты, визуализацию сабагентов, мобильный терминал с QR-логином. Node 22 / TS 5.9 / Fastify 5 / Zod 4 / Vitest.

## Выводы для auto-dev

1. Как компонент или основа не подходит. Модель Codeman: скрейпинг терминала интерактивного Claude Code. Наш Драйвер: Agent SDK streaming (тикет 05). Codeman не знает про GitHub issues, PR, labels, Стадии QA/Merge; его оркестратор ведёт фазы по фразе `<promise>PHASE_N_TASK_M_DONE</promise>` в выводе и детектит idle регекспами по тексту терминала плюс «AI idle checker» (отдельный Claude Opus на проверку IDLE/WORKING, то есть расход нашего же лимита Max). Respawn делает `/clear`, что противоречит нашему «Реализатор = одна живая Сессия». Auto-accept plan mode шлёт Enter по таймеру 8 с.
2. Подтверждение решения 05 от противного: сами авторы фиксируют хрупкость терминального подхода: «A `❯` sighting is NOT the end of a turn, and neither is silence», глиф и герундий индикатора рандомизированы, tmux отдаёт частичные перерисовки. Поток событий SDK этих проблем не имеет.
3. Переносимые наработки: три пункта ниже (лимиты, доставка Ответа, worktree). Плюс идеи UI.

## Переносимое

### A. Расход лимита Max и поведение у стены (тикет 12)

- Единственный канал процентов остатка: JSON statusline, поле `rate_limits.five_hour` / `seven_day` с `used_percentage` (0-100, целые) и `resets_at` (epoch СЕКУНДЫ, умножать на 1000). Подтверждено Codeman на Claude Code 2.1.177 с аккаунтом Max. Поле отсутствует на первом рендере, появляется после первого ответа API. То же, что research 01 п. 9, плюс точная форма.
- Лимиты общие на аккаунт (5h/7d пулы), значит показывать один индикатор на Установку, «свежайшая выборка побеждает», а не по Агенту.
- Пороги подсветки Codeman: зелёный < 60%, жёлтый 60-84%, красный >= 85%.
- Инъекция statusline у Codeman: эфемерный флаг `claude --settings` при запуске, оборачивает statusline пользователя, никогда не пишется в `settings.json` на диске (у них была реальная бага: записанный statusline перекрывал пользовательский для любых запусков `claude` в каталоге). Для нас: если собирать проценты через statusline, то только через настройки процесса Агента, не через файлы Продукта.
- Для SDK-драйвера сначала проверить, достаточно ли `rate_limit_event.rate_limit_info.utilization` из stream-json (research 01 п. 9): если он приходит и в обычном (не rejected) статусе, statusline не нужен вовсе. Не подтверждено.
- Auto-resume Codeman: при стене парсит время сброса, ставит таймер на reset + 2 мин, при повторном отказе ретрай через 5 мин, переход в `working` отменяет. Пока «на паузе» respawn запрещён (иначе `/clear` стирает контекст). Для нас аналог: при `rate_limit_event` со status rejected Оркестратор не стартует новые Ходы до `resetsAt + 2 мин`, живые Сессии не трогает; «пре-арм» по процентам (не стартовать новый Ход при >= 95%) Codeman не построил, но отметил как следующий шаг.

### B. Доставка Ответа в живую Сессию ровно один раз (тикеты 07, 09)

Проблема у Codeman: half-open WebSocket, `send()` не падает, кадр теряется, промпт исчезает без следа. Решение, переносимое на наш Диалог из UI и на Ответ из комментария GitHub:

- Клиент хранит стабильный `clientId` и монотонный per-session `seq`; каждый отправленный кадр записывается в localStorage до отправки и удаляется только по ACK сервера `{seq}`. Счётчик seq никогда не сбрасывается (сброс превратит новый ввод в «уже применённый дубль»).
- Сервер применяет `(clientId, seq)` ровно один раз: первый seq строго больше последнего применённого для этого клиента. Дубль получает ACK с `dup: true, last: <watермарк>`, клиент поднимает свой счётчик до `last`. Без `last` у них была «тихо мёртвая» вкладка: клиент после краша считал ниже сервера, всё дропалось с ACK.
- Фоновый sweep каждые 2 с: если старейший кадр без ACK дольше 4 с, сокет считается мёртвым, принудительный reconnect и повторная отправка всех pending.
- Третий исход кроме «применено» и «ретрай»: «отказано навсегда» (400/413, превышение размера), такие кадры дропаются, иначе ядовитый кадр блокирует очередь вечно.
- Известное ограничение: дедуп в памяти сервера, рестарт в окне между записью и ретраем может дать редкий дубль; выбрано «не терять ввод» вместо «никогда не дублировать». Для нас дедуп должен жить в Рантайм-индексе (переживает рестарт Оркестратора), так как Ответ попадает в Сессию как результат tool и дубль ломает Ход.
- Для Ответа из GitHub: идентичность = id комментария, та же семантика «применён ровно один раз», хранить в Рантайм-индексе.

### C. Раскладка worktree (тикет 08, пункт «жизненный цикл worktree»)

Codeman кладёт worktree в `<repo>/.claude/worktrees/<name>` на ветке `worktree-<name>`, имена `[A-Za-z0-9._-]` до 64 символов. Это ровно раскладка нативного `claude --worktree` (измерено ими на 2.1.296). Для нас: использовать ту же раскладку либо прямо `--worktree`/`worktree`-опцию SDK, чтобы не изобретать свою и чтобы `claude` внутри VM видел worktree как свой. Проверить: имя = `issue-<N>` проходит по алфавиту; `.claude/worktrees` должен быть в exclude Продукта (Codeman пишет exclude сам).

### D. Идеи UI для Режима разработки (тикеты 14, 15)

- Tile grid: до 6 живых Агентов плиткой на одном экране.
- Визуализация сабагентов плавающими окнами с линиями к родительской Сессии (у нас данные есть из `SDKMessage` с `parent_tool_use_id`).
- QR-логин с телефона: одноразовый токен, bind на loopback по умолчанию, проверка Host/Origin. Для LAN-доступа (тикет 14) та же модель угроз.
- «Away digest»: сводка, что случилось, пока человека не было. Для нас: список Запросов к человеку и завершённых Задач с момента последнего визита.

## Не переносим

- Respawn-цикл `/clear` + `/init`, AI idle checker, AI plan checker, auto-accept plan mode: противоречат модели Сессии и жгут лимит.
- Агентский control plane (`codeman agent spawn/send/wait`, MCP с 7 tools, wait-primitives): нужен, когда один агент рулит другими через терминал; у нас Оркестратор на SDK.
- Hook `elicitation_dialog` для перехвата AskUserQuestion: у нас AskUserQuestion запрещён через `disallowedTools` (тикет 05).
- Поддержка других CLI, Docker/SSH-кейсы, Discord-мост, голос, жесты: out of scope.
