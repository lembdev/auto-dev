# Стадия merge: метод слияния, конфликты, CI, закрытие issue и milestone

Type: grilling
Status: resolved
Blocked by: 06

## Question

Что делает merge-агент: метод (squash / merge / rebase), что если main ушёл вперёд (rebase worktree и повторный QA или нет), как резолвит конфликты и когда эскалирует человеку, нужно ли ждать CI, кто закрывает issue (авто через closes #N или агент), когда и кто закрывает milestone, что происходит с worktree и веткой после merge.

## Notes

- Из research 03: draft PR в приватном личном репо недоступен (только Team/Enterprise): решить замену (обычный PR + label/WIP-заголовок). Merge через `PUT .../merge` (merge/squash/rebase) или `merge-async`; `closes #N` срабатывает только при merge в default branch; токену нужен Contents write.
- Из тикета 06: issue закрывает GitHub через `Closes #N` в теле PR (тело пишет оркестратор при создании PR); после merge оркестратор снимает метку `auto-dev:*` и чистит рантайм; milestone закрывает оркестратор при `open_issues == 0`; PR, закрытый человеком без merge, переводит задачу в failed.
- Референс Breedly/breedly-ios (sandcastle/main.ts): ветка на тикет, implement -> verify (ступень по метке тикета, выбирает драйвер, не агент) -> review со структурированным вердиктом {approved, summary, blockers[{where, what}]} -> до N попыток починки -> merge в main -> закрыть тикет комментарием и снять `ready-for-agent`; прогон, закрывший последнюю задачу вехи, закрывает зонтик, спеку и саму веху; веха с любым другим открытым тикетом не закрывается. Задачи приёмки у нас нет (решение по 06). Красный тикет: комментарий с причиной, `ready-for-agent` снимается, ставится `ready-for-human`; если красна оснастка (infrastructure), `ready-for-agent` остаётся. Упор в лимит: тикет не помечается, цикл просто останавливается.
- Из контракта breedly-api: при закрытии Задачи отмечать соответствующие критерии закрытия в Epic (чек-лист в теле Epic); milestone закрывать, когда закрыты все issues вехи и все критерии Epic отмечены, тогда же закрывать Epic и Spec.

## Answer

Решено 2026-11-05 (grilling; пользователь принял рекомендации без правок). Факты на дату: Breedly/breedly-api приватный org на Free, draft PR и branch protection недоступны, CI-workflow нет, разрешены squash/merge/rebase.

1. **Метод.** Squash через `merge-async`. Сообщение squash-коммита = заголовок PR, одна строка Conventional Commits, тело пустое. Коммиты Агента внутри ветки произвольные.
2. **Замена draft.** PR создаёт Оркестратор при старте Реализации с префиксом `WIP: ` в заголовке; после вердикта approved префикс снимается. Draft не используется нигде, даже где доступен: одно поведение.
3. **Кто сливает.** Оркестратор сам вызовом API, без Агента; перед этим проверяет `mergeable`. При конфликте поднимается Merger-агент в worktree: `git merge origin/main`, резолв, push. Merger существует только для конфликтов.
4. **После резолва.** Один дополнительный Круг QA по итоговому diff, в лимит Кругов не засчитывается; замечания идут Реализатору как обычно.
5. **CI.** Есть check-runs или статусы на PR: ждём завершения. Красный = замечание Реализатору, засчитывается как Круг. Нет checks = не ждём. Checks висят дольше часа = тупик `ready-for-human`.
6. **Закрытие issue и критерии Epic.** После подтверждённого merge Оркестратор закрывает issue явно (`state_reason: completed`); `Closes #N` в теле PR для связи. Реализатор пишет в тело PR секцию `## Критерии Epic` с точными строками чек-листа Epic; после merge Оркестратор ставит `[x]` на совпавшие строки. Нет секции = ничего не отмечает.
7. **Milestone.** При опросе: все issues вехи закрыты и все критерии Epic отмечены = закрыть Epic, Spec, milestone. Issues закрыты, критерии нет = milestone открыт, на Epic `ready-for-human` с комментарием «не отмечены критерии: ...».
8. **После merge.** Ветка на GitHub удаляется; Сессия Реализатора закрывается (процесс гасится, транскрипт в `sessionStore`); итоговый комментарий Оркестратора в issue с маркером: ссылка на PR и Сессию. Локальная чистка worktree и веток - тикет 19.

Последствия для карты: разблокированы 19 (ждал только 11) и наполовину 18 (ждёт ещё 16); в 18 добавлены требования к промптам (секция `## Критерии Epic`, Merger только конфликты).
