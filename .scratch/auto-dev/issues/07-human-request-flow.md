# Поток запроса к человеку: семантика ask_human и маршрутизация ответа

Type: grilling
Status: resolved
Blocked by: 05

## Question

Детали tool ask_human: что агент передаёт (вопрос, варианты, контекст), что оркестратор пишет в issue, как помечает агента «ждёт». Как ответ попадает в сессию: из комментария GitHub (как отличить ответ от прочих комментариев, чей комментарий считается ответом) и из UI (интерактивный диалог, несколько сообщений подряд). Что если ответили и там и там. Что если оркестратор перезапустился пока агент ждал. Таймаут ожидания есть ли.

## Notes

- Из research 03: с PAT комментарий оркестратора неотличим от комментария владельца; GitHub App даёт `user.type == "Bot"`. Выбор PAT vs App решает, как отличать Ответ человека. Polling комментариев 15-20 с с ETag.
- Из research 02: `canUseTool` callback может ждать неограниченно; для долгих ожиданий есть `defer` + resume. ask_human можно реализовать как in-process MCP tool, чей результат возвращается после Ответа.
- Из тикета 05: ask_human = in-process MCP tool + PreToolUse `defer`; в Ожидании процесс Агента гасится, Ответ доставляется через `resume` как результат того же вызова. Механика проверяется прототипом 16. AskUserQuestion запрещён.
- Из research 05 (Codeman): Ответ в Сессию доставлять ровно один раз: у Ответа из UI идентичность `clientId` + монотонный `seq`, у Ответа из GitHub id комментария; Оркестратор помечает применённые в Рантайм-индексе (переживает рестарт), дубль подтверждает, но не применяет. Третий исход «отказано навсегда» (например, слишком большой ввод), чтобы ядовитое сообщение не блокировало очередь.
- Референс Breedly/breedly-ios: передача человеку = комментарий в тикете с телом (что сделано, что красное, лог) + метки `ready-for-human` вместо `ready-for-agent`. У нас Ожидание не равно передаче: Сессия жива и ждёт Ответа. Нужно определить, чем отличаются в labels `waiting` (ждёт Ответа) и «отдано человеку насовсем» (failed / ready-for-human).

## Answer

Решено 2026-11-05 (grilling; пользователь принял рекомендации без правок).

1. **Контракт tool ask_human.** Два поля: `question` (текст, обязательно) и `options` (список коротких вариантов, необязательно). Поля «контекст» нет: всё нужное Агент пишет в вопрос. Результат tool: текст Ответа плюс одна строка «кто и откуда» (GitHub-комментарий с ссылкой или UI). Ответ человека всегда свободный текст, варианты только подсказка.
2. **Публикация Запроса.** Оркестратор пишет ровно один комментарий на один Запрос в issue Задачи (не в PR), по шаблону: Стадия Агента, вопрос, варианты списком, строка «ответьте комментарием здесь или в UI». Ответ ищется только в issue Задачи.
3. **Свой / чужой комментарий: PAT + маркер, без GitHub App.** Оркестратор работает от PAT и кладёт в каждый свой комментарий скрытый маркер (HTML-комментарий `<!-- auto-dev -->`). Ответ = первый комментарий в issue после комментария-Запроса без маркера, от любого пользователя (владелец и коллабораторы). Агент в Ожидании не пишет в GitHub, поэтому его комментарии с Ответом не путаются. GitHub App ушёл в Out of scope.
4. **Подтверждение приёма.** На комментарий, взятый как Ответ, Оркестратор ставит реакцию 🚀. Отдельного комментария «принято» нет.
5. **Ответ из UI зеркалится в GitHub.** Оркестратор пишет его в issue комментарием с маркером («Ответ из UI: ...»), чтобы история Запросов и Ответов целиком лежала в GitHub.
6. **Два канала и несколько сообщений.** Ответом становится первое сообщение, которое Оркестратор получил (по времени получения, не написания), из любого канала. Всё последующее не теряется: доставляется в ту же Сессию как обычные сообщения Диалога, по одному, каждое после конца текущего Хода. Семантика Диалога - тикет 09.
7. **Таймаута нет.** Агент ждёт сколько угодно; Слот свободен; Задача показана в UI как ждущая. Напоминания вне браузера - фог «Уведомления».
8. **Рестарт Оркестратора в Ожидании.** Открытый Запрос хранится в Рантайм-индексе: session id, id вызова tool, id комментария-Запроса, время публикации. После рестарта Оркестратор продолжает ждать и подхватывает Ответ первым опросом комментариев с `since` = время Запроса. Применённые Ответы (id комментария GitHub или `clientId`+`seq` из UI) хранятся в индексе: дубль подтверждается, но не применяется. Структура индекса - тикет 08.
9. **По умолчанию, без обсуждения:** правка или удаление комментария-Ответа после доставки ничего не меняет; у одного Агента в один момент не больше одного открытого Запроса (tool синхронный); ask_human доступен всем Стадиям.

Последствия для карты: фог «промпты Стадий» стал тикетом 18 (контракт Задачи из 06 и ask_human из 07 зафиксированы); в 08 и 09 добавлены заметки; GitHub App в Out of scope.
