# Веб-UI: фреймворки, транспорт реального времени, доступ в LAN

Type: grilling
Status: resolved
Blocked by: 09

## Question

Конкретный стек UI и сервера (например Hono/Fastify + React/SolidJS, или SSR), транспорт для живых событий (WebSocket / SSE), нужна ли авторизация в домашней сети (нет / basic / токен), HTTPS или нет, порт. Решение после выбора подхода к живому виду (09).

## Notes
- Из research 05 (Codeman): их модель доступа: bind на loopback по умолчанию, пароль опционально, проверка Host/Origin, одноразовый QR-токен для входа с телефона. Для LAN-доступа Установки рассмотреть ту же схему.

## Answer

Решено 2026-11-05 (рекомендации агента, принятые пользователем заранее).

1. **Один процесс:** Оркестратор и веб-сервер в одном Node-процессе (один systemd unit, общий Рантайм-индекс в памяти процесса).
2. **Сервер:** Hono на Node. REST для состояния и действий, WebSocket (`ws`) для live-событий и Диалога (двусторонний канал нужен, SSE отвергнут). Один WS на вкладку, подписка на Агентов по id.
3. **Клиент:** React + Vite + TypeScript, SPA, статика отдаётся тем же сервером. Данные: TanStack Query + события из WS; стили Tailwind; без UI-кита.
4. **Доступ:** bind `0.0.0.0:8080`, HTTP без TLS (домашняя LAN; reverse proxy с TLS вне scope). Один общий пароль Установки, задаётся при первом запуске (тикет 20), cookie-сессия 30 дней. Проверка `Origin` на WS и `Host` на HTTP. QR-вход с телефона и несколько пользователей вне scope.
