# Обновление уже развёрнутых установок auto-dev

Type: grilling
Status: open
Blocked by: 04

## Question

Как исправления в auto-dev попадают в существующие VM: режим update скрипта установщика (как в community-scripts), команда/кнопка в UI, автообновление по таймеру. Как версионируется auto-dev (теги, релизы), как мигрируется локальный индекс, что с запущенными агентами во время обновления. Рекомендация: git-clone по тегу + режим update в скрипте + кнопка в UI.

## Notes

- Из research 04: штатный путь - `update_script()` в ct-скрипте + `/usr/bin/update` в контейнере + релизы GitHub (`fetch_and_deploy_gh_release`, `check_for_gh_release`); массовое обновление с хоста `pct exec ... update`. Решить: релизы auto-dev как GitHub Releases (tag + архив) и что делать с запущенными агентами и Рантайм-индексом при обновлении. Репо скриптов должен быть публичным.
- Из тикета 05: системный `claude` обновляется автоапдейтером независимо от релизов auto-dev; оркестратор делает smoke-query при смене версии. Решить здесь: нужна ли кнопка «откатить claude» и как update-скрипт ставит/переустанавливает бинарь.
