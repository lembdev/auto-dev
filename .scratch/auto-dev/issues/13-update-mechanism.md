# Обновление уже развёрнутых установок auto-dev

Type: grilling
Status: resolved
Blocked by: 04

## Question

Как исправления в auto-dev попадают в существующие VM: режим update скрипта установщика (как в community-scripts), команда/кнопка в UI, автообновление по таймеру. Как версионируется auto-dev (теги, релизы), как мигрируется локальный индекс, что с запущенными агентами во время обновления. Рекомендация: git-clone по тегу + режим update в скрипте + кнопка в UI.

## Notes

- Из research 04: штатный путь - `update_script()` в ct-скрипте + `/usr/bin/update` в контейнере + релизы GitHub (`fetch_and_deploy_gh_release`, `check_for_gh_release`); массовое обновление с хоста `pct exec ... update`. Решить: релизы auto-dev как GitHub Releases (tag + архив) и что делать с запущенными агентами и Рантайм-индексом при обновлении. Репо скриптов должен быть публичным.
- Из тикета 05: системный `claude` обновляется автоапдейтером независимо от релизов auto-dev; оркестратор делает smoke-query при смене версии. Решить здесь: нужна ли кнопка «откатить claude» и как update-скрипт ставит/переустанавливает бинарь.
- Решение по 08 (2026-11-05): данные Установки в `/var/lib/auto-dev` (`runtime.db`, клон `repo/`); обновление обязано сохранять этот каталог и прогонять миграции схемы только вперёд.

## Answer

Решено 2026-11-05 (рекомендации агента, принятые пользователем заранее).

1. **Версии:** SemVer теги `vX.Y.Z` + GitHub Releases с архивом собранного приложения. Репо `lembdev/auto-dev` становится публичным с первого релиза (community-scripts требуют публичный репо скриптов; отдельный репо скриптов не заводим).
2. **Раскладка:** `/opt/auto-dev/releases/<v>` + симлинк `/opt/auto-dev/current`; данные `/var/lib/auto-dev`; конфиг и секреты `/etc/auto-dev/` (тикет 20). Сервис `auto-dev.service` (systemd) от пользователя `auto-dev`.
3. **Канал обновления:** штатный путь community-scripts: `update_script()` в ct-скрипте + `/usr/bin/update` в контейнере через `fetch_and_deploy_gh_release`. Кнопка «Обновить» в UI вызывает тот же `update` через sudo-правило NOPASSWD только на эту команду. Автообновления по таймеру нет; раз в сутки проверка новой версии, баннер в UI.
4. **Процедура:** Пауза взятия -> ждать конца текущих Ходов до 10 мин, потом `interrupt()` -> stop service -> deploy новой версии -> миграции схемы вперёд -> start -> штатный рестарт по 08 (resume всех). Откат `update --rollback`: переключение симлинка на предыдущий релиз; только если версия схемы совпадает, иначе отказ с сообщением.
5. **Бинарь `claude`:** установщик ставит native installer от пользователя `auto-dev`, автообновление включено (05). Кнопки «откатить claude» нет: при провале smoke-query UI показывает ошибку и команду `claude install <предыдущая версия>` для ручного выполнения.
