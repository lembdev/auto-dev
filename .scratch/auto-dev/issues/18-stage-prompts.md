# Промпты Стадий: Реализация, QA, Merge

Type: grilling
Status: resolved
Blocked by: 11, 16

## Question

Содержимое системных промптов трёх Стадий. Что общего (карта репо, что прочитать до правки, один тикет на ветку, запрет ставить labels и писать статус-комментарии, когда звать ask_human, формат коммитов и PR). Реализатор: как начинает, что считает готовым, как принимает замечания QA в живую сессию. QA: входные данные (diff PR, issue, критерии Epic), структурированный вердикт `{approved, blockers}`, что проверяет сам (тесты, линт), чего не делает (не правит код). Merger: что делает при конфликте, что при красном CI, как закрывает Задачу. Что из промптов живёт в auto-dev, а что Продукт может переопределить у себя (например `docs/agents/*.md`).

## Notes

- За основу: implement/review промпты Breedly/breedly-ios (`.sandcastle/implement-prompt.md`, `review-prompt.md`), без SwiftUI-шагов (кадры, симулятор, a11y).
- Из 05: граница «labels и статус-комментарии ставит Оркестратор» держится только промптом; `AskUserQuestion` отключён, вопросы только через ask_human.
- Из 06: Оркестратор берёт только Task/Bug с `ready-for-agent`; закрытие через `Closes #N` в теле PR; критерии Epic отмечает Задача.
- Из 07: ask_human принимает `question` + `options`, Ответ свободный текст; в Ожидании Агент не пишет в GitHub.
- Ждёт 11 (политика merge и CI) и 16 (подтверждённая механика ask_human).
- Решение по 11 (2026-11-05): Реализатор обязан писать в тело PR секцию `## Критерии Epic` с точными строками чек-листа Epic; заголовок PR = одна строка Conventional Commits (станет squash-коммитом); Merger поднимается только при конфликте (`git merge origin/main`, резолв, push), после него ещё один Круг QA; красный CI приходит Реализатору как замечание.
- Решение по 16 (2026-11-05): ask_human = stdio MCP tool, результат приходит текстом в том же вызове; промпт говорит Агенту: «ответ может прийти не сразу, после вызова ask_human не продолжай работу, жди результата».

## Answer

Решено 2026-11-05 (рекомендации агента, принятые пользователем заранее).

1. **Где живут промпты.** В auto-dev: `prompts/common.md`, `prompts/implement.md`, `prompts/qa.md`, `prompts/merge.md`, `prompts/plan.md`, в сборку как текст. Продукт переопределять их не может; вместо этого промпт обязывает Агента прочитать `CLAUDE.md`, `GLOSSARY.md`, `docs/agents/*.md` и `docs/adr/` Продукта: там правила Продукта. Шаблонные подстановки: номер и тело issue, Epic и его критерии, номер PR, ветка, Круг, вердикт QA.
2. **Общая часть** (`common.md`): ты Агент auto-dev, Стадия такая-то; работай только в своём worktree и ветке; один issue = один PR; коммиты Conventional Commits одной строкой; не ставь labels, assignee, milestone и не пиши комментарии-статусы в issue и PR, это делает Оркестратор; не закрывай issue и PR; вопросы человеку только через `ask_human` (`question`, `options`), после вызова жди результата, он может прийти через часы; не трогай `.claude/worktrees`, `/etc/auto-dev`, `/var/lib/auto-dev` вне worktree; не ослабляй и не выключай тесты ради зелёного.
3. **Реализатор** (`implement.md`): прочитай issue, Parent Epic и критерии, тело Spec; изучи карту репо (CLAUDE.md, глоссарий, ADR, структуру) до правок; реализуй What to build так, чтобы выполнялись все Acceptance criteria; прогоняй тесты и линт Продукта; в конце: все изменения закоммичены и запушены, тело PR заполнено по шаблону: `Closes #N`, «Что сделано», «Как проверить», `## Критерии Epic` с точными строками чек-листа Epic (или «нет»). Замечания QA приходят следующим сообщением в ту же Сессию: исправь каждое из `blockers`, снова прогони тесты, запушь, ответь кратким списком «что исправлено».
4. **QA** (`qa.md`, новая Сессия каждый Круг): вход: issue с критериями, diff PR, тело PR, вердикт прошлого Круга (если есть). Проверяй по Acceptance criteria и критериям Epic из тела PR; прогони тесты и линт сам; код не правь, коммитов не делай. Выход: ровно один JSON в последнем сообщении: `{ "approved": boolean, "summary": string, "blockers": [{ "where": string, "what": string }] }`; approved только при пустых blockers; замечания по стилю не блокируют. Оркестратор парсит JSON; не распарсилось = повтор Круга с просьбой выдать только JSON, второй провал = тупик.
5. **Merger** (`merge.md`, только конфликт): в worktree выполни `git merge origin/main`, разреши конфликты, сохранив поведение Задачи и свежего main, прогони тесты, закоммить и запушь; код сверх конфликтов не меняй; выход: одна строка «готово» или `ask_human`, если конфликт требует решения человека.
6. **Планировщик** (`plan.md`): роль Планировщика из 10; обязан прочитать `docs/agents/issue-tracker.md` Продукта и следовать ему; работает через skills `/wayfinder`, `/to-spec`, `/to-tickets`; ничего не коммитит; перед созданием читает открытые milestones и issues.
7. **Ограничения по размеру.** Контекст Агента не контролируется промптом: компакция штатная. Лимит Хода по времени нет; завис Агент (нет событий 30 мин) = `interrupt()` и resume с сообщением «продолжай», второй раз = тупик.
