# Живой вид агента и интерактивный диалог: выбранный подход

Type: grilling
Status: resolved
Blocked by: 02, 05

## Question

Как UI показывает конкретного агента (поток событий / терминал / транскрипт) и как человек общается с ним интерактивно. Выбор между: собственный чат поверх SDK-потока; tmux + web-терминал; встраивание готового UI; Remote Control. Что видно при обычной работе агента (мониторинг) и что при ожидании человека (микроменеджмент). Решение после research 02 и выбора драйвера.

## Notes

- Из research 01: Remote Control под `CLAUDE_CODE_OAUTH_TOKEN` не работает (токен "can only make model requests"), вариант отпадает, если auth через setup-token.
- Из research 02: рекомендация SDK-поток -> WebSocket -> свой чат; tmux+ttyd как запасной «сырой терминал»; Remote Control только как мобильный канал и только без setup-token; JSONL формат внутренний, для истории использовать `sessionStore`.
- Из тикета 05: драйвер = Agent SDK streaming input, события `SDKMessage` + `sessionStore`; Remote Control отпадает (setup-token).
- Из research 05 (Codeman): для Диалога из UI брать их схему надёжной доставки: кадр записывается у клиента до отправки и удаляется только по ACK сервера; сервер дедуплицирует `(clientId, seq)`, в ACK дубля отдаёт watermark; sweep 2 с / таймаут ACK 4 с принудительно переподключает мёртвый сокет. Идеи вида: tile grid до 6 Агентов, окна сабагентов с линиями к родителю.
- Решение по 07 (2026-11-05): Ответ = первое полученное сообщение из любого канала; всё последующее доставляется в Сессию как обычные сообщения Диалога, по одному, каждое после конца Хода. Ответ из UI зеркалится в issue комментарием с маркером `<!-- auto-dev -->`. Здесь решить: как UI показывает открытый Запрос и очередь недоставленных сообщений.
- Решение по 08 (2026-11-05): очередь недоставленных сообщений Диалога = таблица `pending_messages` в Рантайм-индексе; история событий Агента для UI из `sessionStore`, live-стрим из Драйвера; UI ходит в индекс только через API Оркестратора.

## Answer

Решено 2026-11-05 (рекомендации агента, принятые пользователем заранее).

1. **Подход: собственный чат поверх SDK-потока.** tmux+ttyd и встраивание чужого UI не делаем; Remote Control отпадает (setup-token). Транспорт и стек - тикет 14.
2. **Карточка Агента = лента событий** из `SDKMessage`: текст ассистента стримится; вызов tool одной строкой (имя + первая строка input), по клику раскрываются input и результат; системные события (compaction, `rate_limit_event`, `api_retry`) отдельной серой строкой; thinking свёрнут по умолчанию; сабагенты как вложенные блоки внутри ленты родителя, не отдельные окна. При открытии карточки история из `sessionStore.getSessionMessages`, затем live-стрим.
3. **Два состояния карточки.** Работает: лента + поле ввода. Ожидание: карточка подсвечена, наверху открытый Запрос: текст, `options` кнопками, поле свободного текста. Отправка = Ответ (07): Оркестратор зеркалит в issue и делает resume.
4. **Диалог во время работы.** Поле ввода доступно всегда. Сообщение попадает в `pending_messages` и доставляется как user-сообщение после конца текущего Хода (streaming input SDK). UI показывает очередь «ещё не доставлено», сообщение можно удалить до доставки. Доставка ровно один раз: `clientId` + `seq`, ACK с watermark, sweep 2 с / таймаут 4 с (research 05).
5. **Управление Агентом из UI:** две кнопки: «Остановить ход» (`interrupt()`, Сессия жива) и «Отменить задачу» (сценарий Отмены из 06: закрыть issue). Другого ручного управления нет.
6. **Мониторинг.** Список Задач в работе со Стадией, Кругом и состоянием Агента; детали - прототип 15.
