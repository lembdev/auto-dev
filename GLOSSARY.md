# auto-dev

Комплекс для автономной (24/7) и полуавтономной разработки ПО поверх Claude Code, работающий на выделенной VM в домашнем Proxmox и ведущий один продукт в одном GitHub-репозитории.

## Language

### Установка и продукт

**Продукт (Product)**:
Разрабатываемое ПО, живущее в одном GitHub-репозитории.
_Avoid_: проект, репо (как синоним продукта)

**Установка (Installation)**:
Один экземпляр auto-dev на одной VM, привязанный ровно к одному Продукту.
_Avoid_: инстанс комплекса, сервер

**Установщик (Installer)**:
Скрипт в стиле Proxmox Community Scripts, создающий VM с Установкой и умеющий её обновлять.

### Работа

**Задача (Task)**:
GitHub issue Продукта, которую Оркестратор ведёт через Конвейер. Issue - единственный источник правды о состоянии Задачи.
_Avoid_: тикет, таск

**Milestone**:
GitHub milestone; группа Задач, закрываемая, когда закрыта последняя Задача в нём.

**Готовая Задача (Ready task)**:
Задача в очереди, у которой нет открытых блокеров. Только такие Оркестратор берёт в Конвейер.
_Avoid_: доступная, свободная

**Отмена (Cancellation)**:
Прекращение работы над Задачей по воле человека: issue закрыта без влитого PR. Оркестратор гасит Агента и убирает следы.
_Avoid_: пауза, стоп

**Оркестратор (Orchestrator)**:
Фоновый процесс Установки: берёт Задачи, создаёт worktree и PR с префиксом `WIP:`, запускает Агентов по Стадиям, ведёт Рантайм-индекс.

**Агент (Agent)**:
Один инстанс Claude Code, запущенный Оркестратором для одной Стадии одной Задачи.
_Avoid_: воркер, бот

**Стадия (Stage)**:
Шаг Конвейера, выполняемый Агентом: Реализация, QA, Merge.

**Конвейер (Pipeline)**:
Последовательность Стадий одной Задачи: Реализация -> QA (с Кругами) -> Merge.

**Реализатор (Implementer)**:
Агент Стадии Реализации. Одна живая сессия на всю жизнь Задачи: правки по замечаниям QA идут в неё же.

**QA**:
Агент Стадии QA. Каждый Круг - новый инстанс с чистым контекстом.

**Круг (Round)**:
Одна проверка QA и ответные правки Реализатора. Число Кругов ограничено; по исчерпании - Запрос к человеку.

**Merger**:
Агент Стадии Merge, поднимается только при конфликте с main: резолвит его в worktree. Само слияние, закрытие Задачи и Milestone делает Оркестратор.

**Сессия (Session)**:
Идентичность Агента: session id Claude Code и его транскрипт. Переживает остановку процесса и рестарт Оркестратора; продолжается через resume.
_Avoid_: процесс (как синоним Агента)

**Ход (Turn)**:
Один цикл работы Агента от входящего сообщения до результата. Процесс Агента живёт во время Хода и короткое время после; в Ожидании гасится.

**Драйвер (Driver)**:
Слой Оркестратора поверх Claude Agent SDK, который запускает, возобновляет, останавливает Агентов и отдаёт поток их событий.

**Слот (Slot)**:
Единица параллелизма Оркестратора. Ждущий Агент Слот не занимает.

**Пауза (Pause)**:
Состояние Установки, в котором Оркестратор не берёт новые Задачи и не начинает новые Круги; живые Ходы дорабатываются. Включается человеком или самой Установкой (обновление, диск, истёкший токен).

**У стены (At the limit)**:
Состояние Установки после отказа подписки по лимиту: новые Ходы не стартуют до времени сброса, Сессии живы.

**Тупик (Dead end)**:
Задача, которую Оркестратор не может вести дальше: исчерпаны Круги или технический сбой. Передана человеку насовсем, в отличие от Ожидания.
_Avoid_: failed, провал

### Человек в контуре

**Запрос к человеку (Human request)**:
Обращение Агента через tool ask_human. Оркестратор публикует его комментарием в Задаче и переводит Агента в состояние Ожидание.
_Avoid_: блокер, вопрос агента

**Ожидание (Waiting)**:
Состояние Агента, чья сессия жива и ждёт Ответа, не занимая Слот.

**Ответ (Answer)**:
Первое сообщение человека после Запроса, из комментария GitHub или из Диалога в UI; попадает в ту же сессию Агента как результат Запроса. Последующие сообщения - уже Диалог.
_Avoid_: реплай, фидбек

**Диалог (Dialogue)**:
Интерактивное общение человека с конкретным Агентом из веб-UI. Диалог ведётся и с Планировщиком в Режиме планирования.
_Avoid_: чат, микроменеджмент (как термин)

### Интерфейс

**Планировщик (Planner)**:
Сессия Claude Code в Режиме планирования: превращает замысел человека в Milestones и Задачи. Не занимает Слот, ничего не коммитит.

**Режим планирования (Planning mode)**:
Экран UI, где человек с сессией Claude Code на ветке main превращает замысел в Milestones и Задачи с зависимостями и labels.

**Режим разработки (Development mode)**:
Экран UI с мониторингом Задач и Агентов и входом в Диалог.

**Рантайм-индекс (Runtime index)**:
Локальное хранилище Установки и единственный источник правды о Стадии: связь Задача -> Стадия -> сессия -> процесс -> worktree -> PR, открытые Запросы, применённые Ответы и история переходов Стадий. Не содержит транскриптов и текстов Запросов.
_Avoid_: база данных (как термин)
